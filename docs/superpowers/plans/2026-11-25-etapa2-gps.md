# Etapa 2 — GPS, POS automático e bateria — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ler o NEO-6M e mostrar posição, velocidade, altitude, satélites, hora local (UTC-3) e rumo. Enviar POS a cada 30 s quando houver fix. Manter a posição do SOS atualizada. Medir a bateria. Calcular a distância e a direção até o amigo, visíveis no console.

**Architecture:** A lógica pura vai para `lib/geo` (distância, rumo, hora local, rumo mantido parado, agendador de POS) e `lib/power` (curva da bateria), com testes nativos. O `src/gps.*` alimenta o TinyGPSPlus dentro da task de rádio, como pede o spec ("GPS/LoRa numa task"). O `src/battery.*` lê o ADC. O estado sai via `SharedState`.

**Tech Stack:** TinyGPSPlus, Arduino-ESP32 (`analogReadMilliVolts`), Preferences, Unity nativo.

**Spec:** `docs/superpowers/specs/2026-11-25-dispositivo-gps-lora-design.md` (seções GPS, Bateria, Persistência)

## Global Constraints

- GPS em `Serial1`, 9600 baud, ESP_RX=44, ESP_TX=43. RX buffer de 2048 bytes, porque `loraWrite` pode bloquear a task por até 3 s, e a 9600 baud isso dá cerca de 3 KB.
- Fix válido: `location.isValid()` e `location.age() < 3000` ms.
- Hora exibida em UTC-3 fixo (o Brasil não tem horário de verão desde 2019), com virada de dia, mês e ano.
- Rumo: `gps.course` quando a velocidade passa de 2 km/h. Parado, mantém o último rumo e marca `courseStale = true`.
- POS a cada 30 000 ms com fix, mais jitter de 0–3000 ms (sem jitter, dois aparelhos que colidem uma vez colidiriam sempre). O primeiro POS sai assim que o fix chega. Sem fix, nada sai.
- SOS sempre com a última posição conhecida. Posição desconhecida vai como `0.00000,0.00000`, e quem recebe não atualiza a posição do amigo com esse valor.
- NVS: última posição e último rumo, gravados no primeiro fix e depois a cada 10 min com fix. Isso poupa a flash.
- Bateria: `analogReadMilliVolts(1) × 2`, média exponencial (α = 0,2) a cada 1 s, curva Li-ion por tabela e aviso abaixo de 15%.
- Commits semânticos **sem** linha `Co-Authored-By` (pedido do usuário).

## Review Focus

1. **Virada de dia na conversão UTC → UTC-3:** 01:30 UTC de 1º de janeiro de 2027 tem que virar 22:30 de 31/12/2026. Dia 1º de março em ano bissexto volta para 29/02. Teste: Task 2.
2. **Parado ou com velocidade ruidosa abaixo de 2 km/h:** o rumo não pode pular para o `course` de lixo que o NEO-6M dá parado. Teste: Task 2, `test_course_held_when_slow`.
3. **Sem fix nenhum ao disparar SOS:** vai `0,0`, e quem recebe não move o amigo para o Golfo da Guiné. Teste: Task 1, `test_pos_unknown`. A regra entra na task de rádio (Task 4).
4. **Fix perdido no meio (túnel, mata fechada):** o POS para enquanto não houver fix e volta assim que o fix retorna, sem enviar dados velhos. Teste: Task 2, `test_pos_scheduler_*`.
5. **Rumo até o amigo cruzando 0°/360°:** com o amigo a 350° e meu rumo em 10°, a seta relativa tem que dar −20°, e não 340°. Teste: Task 1.

### Task 2: Lógica do GPS (hora local, rumo mantido, agendador de POS)

**Files:** Create `lib/geo/gps_logic.h`, `lib/geo/gps_logic.cpp`. Test: `test/test_gps_logic/test_main.cpp`

**Interfaces — Produces:**
```cpp
struct DateTime { uint16_t year; uint8_t month, day, hour, minute, second; };
DateTime utcToLocal(const DateTime& utc, int offsetHours);   // offset -3; trata dia/mês/ano/bissexto

class CourseTracker {
 public:
  explicit CourseTracker(double initialDeg = 0, bool known = false);
  void update(bool valid, double speedKmh, double courseDeg);  // > 2 km/h: aceita o curso
  double course() const; bool known() const; bool stale() const;  // stale = último update não atualizou o rumo
};

class PosScheduler {
 public:
  PosScheduler(uint32_t (*rand32)(), uint32_t periodMs = 30000, uint32_t jitterMaxMs = 3000);
  bool due(uint32_t now, bool hasFix);  // true = enviar POS agora (já reagenda)
};
```
Regras do `PosScheduler`:
- Na transição de sem fix para com fix, `due` retorna true na hora.
- Depois disso, envia quando `now ≥ last + period + jitter` (jitter sorteado a cada envio).
- Sem fix, retorna false e esquece o agendamento, para que o próximo fix envie na hora.

### Task 4: Integração (GPS, bateria, POS automático, console)

**Files:** Create `src/gps.h/.cpp`, `src/battery.h/.cpp`. Modify `src/state.h`, `src/radio_task.cpp`, `src/debug_console.cpp`.

**Interfaces:**
- Consumes: Tasks 1–3 e `Link::sendPos/updateSosPosition/startSos`.
- Produces:
```cpp
// state.h (novos campos em SharedState)
bool gpsFix; double lat, lon; float altM, speedKmh; uint8_t sats;
double courseDeg; bool courseKnown, courseStale;
bool timeValid; DateTime localTime;
bool myPosKnown;                         // fix atual OU última posição salva
uint32_t batteryMv; uint8_t batteryPct; bool batteryLow;
// gps.h
void gpsBegin();                 // Serial1.setRxBufferSize(2048); begin(9600, 8N1, 44, 43); carrega última posição e rumo da NVS
void gpsPoll(uint32_t now);      // alimenta o TinyGPSPlus e atualiza SharedState; grava NVS (1º fix, depois a cada 10 min)
// battery.h
void batteryBegin();             // analogSetPinAttenuation(PIN_BAT_ADC, ADC_11db)
void batteryPoll(uint32_t now);  // a cada 1000 ms: lê, filtra e atualiza SharedState
```
NVS: namespace `"gps"`, chaves `lat`, `lon` e `crs` (double), mais `ok` (bool).

Task de rádio:
- `gpsBegin()` e `batteryBegin()` antes do laço.
- A cada volta: `gpsPoll`, `batteryPoll`, `if (posSched.due(now, fix)) link.sendPos(...)`.
- Com o meu SOS ativo, a cada 5 s: `link.updateSosPosition(posição atual ou última, bat)`.
- Um `RadioCmd::SosStart` com `lat == 0 && lon == 0` (o console manda assim quando não há argumentos) usa a posição atual, ou a última, ou 0,0.
- No `onPacket`, POS ou SOS com `!posKnown(lat, lon)` não atualiza `peerLat/peerLon`.

Console:
- `gps`: imprime fix, lat/lon, alt, velocidade, satélites, rumo (com "(antigo)" se `stale`), hora local e bateria.
- `sos` sem argumentos inicia o SOS com a posição atual.
- `status` passa a imprimir também a distância e a direção relativa até o amigo, quando os dois têm posição.

**Como testar no hardware:**
1. Com o aparelho em céu aberto, `gps` a cada ~10 s. O esperado é o número de satélites subir e o fix chegar em 30–60 s (partida a frio do NEO-6M), com a hora local certa.
2. Nos dois aparelhos com fix: o outro mostra `[RX] POS` a cada 30–33 s.
3. Andando a mais de 2 km/h, o rumo muda. Parado, aparece "(antigo)" e o valor se mantém.
4. `status` mostra a distância até o amigo. Compare com a distância real.
5. Em lugar fechado e sem fix: `sos` sem argumentos usa a última posição salva. Reiniciar o aparelho mantém essa posição.
6. Bateria: com um multímetro no pack, compare `gps` (mV) com o valor real. Se errar mais de 50 mV, ajuste o fator do divisor.
