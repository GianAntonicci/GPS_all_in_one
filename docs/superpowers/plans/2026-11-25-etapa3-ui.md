# Etapa 3 — UI, encoder, OLED e SPI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Interface completa pelo encoder, com TFT em paisagem, OLED de status e fluxo de SOS na tela, substituindo o console serial no uso normal.

**Architecture:** Toda decisão de UI (gestos, navegação, teclado, histórico, formatação, overlays de SOS e regra de tela apagada) fica em `lib/ui_logic`, pura e testada no PC. O `src/` tem os drivers finos (`spi_bus`, `display`, `oled`, `input`) e as telas, que só desenham um modelo já decidido num sprite 320×240 em PSRAM. Uma task de UI no core 1 consome a entrada e os `RadioEvt`.

**Tech Stack:** TFT_eSPI (`TFT_eSprite`), Adafruit_SSD1306, FreeRTOS, LEDC, Unity nativo.

**Spec:** `docs/superpowers/specs/2026-11-25-etapa3-ui-design.md` (complementa `2026-11-25-dispositivo-gps-lora-design.md`)

## Global Constraints

- **TFT:** `setRotation(1)`, 320×240, sprite de 16 bit em PSRAM e envio do quadro inteiro.
  - Redesenha sob demanda, mais 1 Hz em telas com relógio ou idades; no máximo 20 fps.
  - Todo acesso ao SPI fica entre `spiLock()` e `spiUnlock()`.
- **Cores:** fundo `#101418`, bloco `#243040`, seleção `#FFD400` com texto preto.
  - SOS: contagem `#600000`, enviando `#B00000`, recebido `#A06000`, visto `#006000`.
  - SOS do amigo: fundo `#FFD400` com texto preto.
- **Backlight:**
  - LEDC no GPIO 14; brilho de 10–100% em passos de 10; NVS em 0–255.
  - Apaga após 30 000 ms sem entrada, nunca com overlay de SOS.
  - Com a tela apagada, a 1ª entrada só acorda, exceto o Hold2s.
- **Encoder e gestos:**
  - A=4, B=5, SW=6 com `INPUT_PULLUP`; `ENC_STEPS_PER_DETENT = 4`.
  - Debounce de 30 ms. Click é soltar antes de 2000 ms. Hold2s dispara aos 2000 ms ainda pressionado e Hold3s aos 3000 ms. Depois de um Hold, soltar não gera Click.
- **SOS:** contagem de 10 s. Durante ENVIANDO e RECEBIDO, cancelar é Hold3s. Peer SOS tem prioridade na tela.
- **Textos:** rótulos sem acento (fontes ASCII). Mensagens rápidas exatamente "Estou bem", "Preciso de ajuda", "Onde voce esta?", "Venha ate mim", "Ok", "Ferido".
- **Histórico e menu:** 20 mensagens em RAM. Ordem do menu raiz: Amigo, Mensagens, Mapa, GPS, Scanner, Configuracoes.
- **OLED:** SSD1306 0x3C, SDA 8, SCL 18, 400 kHz, atualizado 2× por segundo.
  - Prioridade da linha 2: `LORA ERRO` > `ID REPETIDO` > `AMIGO SOS!` > `SOS ENVIANDO` > `SOS RECEBIDO` > `SOS VISTO` (30 s) > normal.
- **Commits:** semânticos, **sem** `Co-Authored-By`.

## Review Focus

1. **Bounce do encoder e giro rápido:** sequências de quadratura inválidas ou bounce não podem gerar passos fantasmas, e um giro rápido não pode perder detents. Teste: Task 1, `test_quad_*`.
2. **SOS disparado sem querer ou não disparado:** quem segura 2 s com a tela apagada tem que cair na contagem. Quem clica para acordar não pode selecionar nada. Quem solta depois de um Hold não pode gerar Click. Teste: Tasks 1 e 6.
3. **SOS dos dois ao mesmo tempo:** o overlay do amigo fica por cima, Click envia "Vi" e Hold3s cancela o meu. Nenhum dos dois some sem ação. Teste: Task 6.
4. **ACK de uma mensagem antiga chegando depois de outra enviada:** o histórico casa a entrega pelo seq e nunca marca a mensagem errada. Teste: Task 4.
5. **Teclado nos limites:** texto com 48 caracteres não aceita mais letras, ⌫ com o texto vazio não quebra, e ENVIAR com o texto vazio não envia. Teste: Task 3.

### Task 6: Overlay de SOS e regra de tela apagada

**Files:** `lib/ui_logic/sos_overlay.h/.cpp`; Test: `test/test_sos_overlay/test_main.cpp`

**Interfaces:**
- Consumes: `SosState` (de `lora_link.h`), `Gesture`.
- Produces:
```cpp
enum class Overlay : uint8_t { None, Countdown, Sending, Received, Seen, PeerSos };
enum class SosAction : uint8_t { None, StartSos, CancelSos, SendSeen, OpenFriend, CloseOverlay };
class SosOverlay {
 public:
  void requestCountdown(uint32_t now);                 // Hold2s ou queda (etapa 5)
  void sync(SosState mine, bool peerSos, uint32_t now); // estado vindo do rádio
  SosAction onGesture(Gesture g, uint32_t now);         // consome os gestos quando há overlay
  SosAction tick(uint32_t now);                         // contagem chegando a 0 -> StartSos
  Overlay top() const;            // o que desenhar em cheio
  bool showMineStrip() const;     // PeerSos em cima com meu SOS ativo
  uint8_t countdownLeft(uint32_t now) const;  // 10..1
  bool active() const;            // há overlay (a tela não apaga)
};
class WakePolicy {
 public:
  explicit WakePolicy(uint32_t timeoutMs = 30000);
  // Retorna true se a entrada deve ser processada; false se só serviu para acordar.
  bool onInput(Gesture g, bool rotated, uint32_t now);
  void wake(uint32_t now);                      // mensagem, SOS e afins
  void tick(uint32_t now, bool keepOn);         // keepOn = overlay ativo
  bool screenOn() const;
};
```
Regras:
- **Contagem:** Click cancela e leva a None. Hold2s não reinicia a contagem. Ao chegar a 0, `tick` retorna `StartSos` e o overlay fica em `Sending` até o `sync` confirmar.
- **Sending e Received:** Hold3s retorna `CancelSos`; Click não faz nada.
- **Seen:** Click retorna `CloseOverlay`. Um `sync` em Seen abre esse overlay uma vez, e depois de fechado ele não volta enquanto o estado continuar Seen.
- **PeerSos:** tem prioridade em `top()`. Click retorna `SendSeen` e depois `OpenFriend` (duas ações seguidas, numa fila interna de ações pendentes). Hold3s cancela o meu SOS se ele estiver ativo.
- **WakePolicy:** com a tela apagada, Click ou giro retornam false e acendem a tela; Hold2s retorna true e acende. A tela apaga em `timeout` sem entrada, nunca com `keepOn`.

### Task 9: Telas e task de UI

**Files:** Create `src/ui.h/.cpp`, `src/ui_screens.h/.cpp`; Modify `src/main.cpp`

**Interfaces — Produces:**
```cpp
// ui.h
void uiStart(Settings& s);           // task "ui", core 1, prioridade 2, stack 8192
void uiRequestSosCountdown();        // thread-safe (fila), para a etapa 5
```
A task de UI roda a cada 5 ms:
1. Lê os detents e o botão e passa por `ButtonGestures` e `WakePolicy`.
2. Gestos com overlay ativo vão para `SosOverlay`; sem overlay vão para a tela do topo. O Hold2s sem overlay chama `requestCountdown`.
3. Drena `radioNextEvent`, atualizando o `MsgHistory`, o banner de 5 s e o `newMsg`. Com `DEBUG_LOG`, repassa ao `consolePrintEvent`.
4. Chama `SosOverlay::sync/tick` e envia `RadioCmd` para cada `SosAction`.
5. Redesenha quando algo mudou ou a cada 1 s. `WakePolicy::tick(keepOn = overlay.active())`, e o backlight acompanha.
6. Atualiza o OLED a cada 500 ms com `oledLines`, alternando o `blinkPhase`.

As telas (`ui_screens.cpp`) recebem um snapshot de `SharedState` e o modelo e desenham no `frame()`: Menu (grade 3×2), Amigo, Mensagens, Detalhe, Teclado, GPS, Configuracoes (com modo de edição), Em breve, os overlays de SOS, a faixa do meu SOS e o banner. Seguem os mockups e o design da etapa 3.

Configuracoes:
- O ID editado é salvo com `settingsSave` seguido de `ESP.restart()`, depois de mostrar "Reiniciando..." por 1 s.
- Brilho e volume são salvos ao sair do modo de edição.

**Como testar no hardware:**
1. **Ligar:** o OLED mostra `--:--` e o ID. O TFT mostra a grade com Amigo selecionado. Girar percorre os blocos e dá a volta.
2. **Ajustar o encoder:** se um detent andar 2 blocos ou 0, ajustar `ENC_STEPS_PER_DETENT` (2 ou 4).
